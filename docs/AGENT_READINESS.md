# Agent readiness discovery metadata

## Scope

On 2026-10-26 the [Circle seller readiness check](https://agents.circle.com/sell/score?url=unmetxyz.my.id%2F) reported **65/100 runtime-verified**: Discovery 30/30, Payment 35/40, and Agent Consumability 0/30. This is a captured baseline, not a score for the current code or a claim that the listing was rescanned after these changes. The Payment gap included missing declarative currency and price; Agent Consumability reported missing guidance, budget guidance, contact email, and external documentation. No contact email was supplied or added. Multiple payment networks and a contact address were deliberately left out; the published offers must remain supported by the existing payment identity, facilitator, and settlement path.

The OpenAPI document now provides `info.x-guidance`, top-level `externalDocs`, and `POST /v1/opportunities` `x-payment-info`. Guidance distinguishes free `GET /v1/demands` from paid intelligence, explains request filters and unsigned JSON 402 retry, and directs ambiguous payment cases to operator investigation. It does not promise a public status endpoint. The guidance is concise and stays within Circle's recommended approximate 1,000-token budget.

`x-payment-info.price` declares the fixed USD query price. Each `protocols[].x402` entry gives version 2 and the exact accepted scheme, network, asset, amount, and token `extra` from the resolved payment configuration and payment options. The extension omits `payTo` and timeout; the live unsigned challenge remains authoritative for those values and any exact returned offer. No marketplace, `paymentFlow`, or provider credentials are exposed by this metadata.

## Limits and maintenance

The production profile is X Layer Mainnet `eip155:196` at `$0.01`, with USD₮0, USDC, and Global Dollar. Existing payment identity checks still constrain supported schemes, assets, amounts, and networks. The SDK can form a Testnet challenge for local development; synchronize OpenAPI with the same `X402_CHAIN_ID` and `OPPORTUNITY_PRICE` before starting a runtime on that profile. Production still requires explicit `X402_CHAIN_ID=196` and the existing fixed mainnet price guard. Adding a network or asset requires matching validation, facilitator, identity, and settlement support; changing metadata alone does not enable payment support.

Circle's [Agent Marketplace overview](https://developers.circle.com/agent-stack/agent-marketplace) describes a curated catalog of x402 services that accept USDC. Its [Discovery API](https://developers.circle.com/agent-stack/agent-marketplace/discovery-api) exposes `accepts[]` and separates vanilla x402 from Circle Gateway with support flags. [Getting listed](https://developers.circle.com/agent-stack/agent-marketplace/get-listed) requires an OpenAPI document and manual approval at the time of review; publishing compatible-looking metadata alone does not prove listing eligibility. Circle's [seller guide](https://developers.circle.com/agent-stack/agent-marketplace/become-a-seller) distinguishes Gateway nanopayments from optional vanilla x402 integration.

Circle's [Facilitator supported networks](https://developers.circle.com/facilitator-service/supported-networks.md) list Arc, Base, and Polygon PoS. Its [Gateway network list](https://developers.circle.com/gateway/references/supported-blockchains) also omits X Layer. Circle separately announced [native USDC on X Layer](https://www.circle.com/blog/now-available-native-usdc-cctp-on-x-layer) in August 2026, but USDC availability by itself does not establish Gateway or Facilitator support. UNMET uses the OKX facilitator on X Layer; its runtime x402 challenge and this OpenAPI projection do not prove that Circle buyers can settle the offered X Layer assets. Circle-specific payer compatibility and manual marketplace acceptance remain unverified.

Run `bun run sync:payment-discovery` after changing the payment profile, then `bun run check:payment-discovery`. The sync command defaults to the production profile (`196`) and honors configured values such as `X402_CHAIN_ID=1952` for development. Backend payment middleware validates its imported OpenAPI discovery against the resolved profile before initializing payment storage or facilitator services. The static check is also part of the root `check` command and backend regression suite.

This advertises x402 v2 offers only. The [MPP service discovery draft](https://paymentauth.org/draft-payment-discovery-01.html) has a different intent/method model; UNMET does not claim MPP support or publish fabricated MPP offers.
