Privacy Policy

What the hosted UNMET site and API process, what becomes public, and what is stored for recovery.

Effective: November 15, 2026

Scope and wallets

This policy covers the hosted UNMET website and API. Reading the site or using public discovery endpoints requires no UNMET account. Wallet actions use the address you connect and require your wallet's approval. Wallet addresses, transaction hashes, and related chain identifiers are used to show market activity and check transaction results.

Public blockchain

Demand specifications, wallet addresses, amounts, and transactions can appear in public chain data when you create a demand, support it, vote, or move funds. UNMET reads and republishes public demand information. Mainnet x402 transfers are also visible onchain. Other parties can index and copy public chain data. UNMET cannot delete the underlying blockchain record. Keep private details and credentials out of public submissions.

Browser storage

  • sessionStorage holds pending transaction recovery data for the tab. A record can contain the wallet address, chain ID, contract, action identifier, transaction hash, transaction intent, and information used to verify a demand after confirmation.
  • localStorage remembers your light or dark theme. The Docs sidebar also uses sessionStorage to remember which groups you opened.

Clearing site data removes these local records. This can interrupt recovery in the browser. It leaves already-broadcast transactions on the network.

API limits and logs

The API uses client IP addresses in memory to enforce per-route request limits. Operational logs may include timestamps, log levels, request identifiers, request methods and routes, response status, duration, and stable error codes. The application request logger is designed to omit client IP addresses, request bodies, and payment authorization headers.

Payment records

x402 payment records can include identifiers and fingerprints for payment operations, payer and recipient wallet addresses, network, amount, authorization expiry, settlement state, a transaction hash when available, timestamps, and operational error codes. These records help prevent duplicate settlement and reconcile payments with uncertain outcomes.

Settled, failed, or cancelled payment records become eligible for cleanup only after the configured retention period has elapsed since their last update and the payment authorization has expired. Active or unresolved records can be kept for reconciliation. Public blockchain records are unaffected by payment record cleanup. See the payment guide for recovery behavior.

Service discovery data

UNMET stores builder-signed discovery metadata in a separate SQLite store. It records the listing identity, revision, signed payload and hash, signature, latest observation, and last check attempt. Public discovery responses can include service URLs and payment-offer observations. A listing's revision marker can remain after it becomes inactive.

Infrastructure and data handling

Wallet connection can use Reown AppKit and WalletConnect. UNMET disables analytics in its AppKit configuration. RPC providers handle chain requests, and OKX facilitates x402 verification and settlement. Independent builders handle requests and payments you send to their endpoints. These services handle data under their own terms and policies.

The hosted configuration restricts direct access to the backend and stores operational SQLite data separately from public site files. For rules on using the hosted service, see the Terms of Use.
