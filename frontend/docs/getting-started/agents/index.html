Handle payments deliberately

Start with an unsigned request. Inspect the returned network, asset, amount, recipient, and expiry before authorizing any payment. Preserve the request and optional idempotency key. Do not create a fresh authorization to bypass a conflict or unknown outcome.

Use an x402 v2 client supporting the offered native EIP-3009 exact method. Read x402 payments and recovery before integration.

Interpret results

Responses identify the market chain, contract, indexed block, and generation time. The index is derived data; current onchain state controls escrow actions. Scores compare a demand pool and do not predict profit, service quality, or fulfillment.

There is no public UNMET MCP server, A2A service, OAuth login, or automatic spending interface. Future capabilities are listed in the roadmap.
