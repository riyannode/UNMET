x402 payments

Authorize a returned payment offer to buy one Demand Intelligence query.

LIMITED · SUPPORTED OFFERS ONLY

Payment flow

  1. Send a valid unsigned POST /v1/opportunities with Accept: application/json.
  2. Read HTTP 402 and decode the base64 JSON in PAYMENT-REQUIRED.
  3. Inspect the offered scheme, network, asset, amount, recipient, and timeout. Authorize one supported offer with your x402 v2 client.
  4. Replay the same method, path, and JSON body with PAYMENT-SIGNATURE. Preserve your optional Idempotency-Key.
  5. On success, read the paid JSON and base64 settlement metadata in PAYMENT-RESPONSE.

The OpenAPI x-payment-info extension gives machine-readable discovery hints: fixed USD price and x402 version, scheme, network, assets, and amounts. It intentionally omits recipient and timeout, which must come from the unsigned challenge. The client must support native EIP-3009 exact payments for the offered chain and token. OKX operates the facilitator; an OKX-specific wallet is not required. Do not substitute a locally invented payment ID or infer the recipient from the treasury. See the OpenAPI description.

Follow the running service's challenge. Documentation addresses and prices are reference information, not authorization to spend. A browser-like request using both a Mozilla user agent and Accept: text/html may receive an HTML 402 page without PAYMENT-REQUIRED; machine clients should request JSON.

Supported networks and assets

Demand-market wallets and escrow currently target X Layer Testnet 1952. Production intelligence billing is separately configured for X Layer Mainnet 196 (eip155:196). Buying intelligence does not move or fund Testnet escrow.

The current production profile lists USD₮0, USDC, and USDG. Consult OpenAPI x-payment-info for discovery hints and the live challenge for the authoritative recipient, timeout, and accepted terms.

These are Mainnet payment assets, not Testnet escrow addresses. Paid confirmation currently supports the reviewed Mainnet path; a Testnet challenge does not establish paid Testnet support. Other schemes, assets, networks, and Permit2 are not enabled by these instructions.

What payment confirmation means

Paid content is released after official facilitator success, a durable payment record, and matching canonical Mainnet L2 transaction/receipt/token evidence. This confirms current L2 inclusion, not safe/finalized status or Ethereum L1 finality.

The paid path requires durable storage on the supported self-hosted runtime. A runtime without it can return unsigned challenges but rejects submitted payment headers with 503 PAYMENT_STORAGE_UNAVAILABLE.

Idempotency

Durable mode optionally accepts Idempotency-Key: 1–128 printable non-space ASCII characters. Retain the same key for the same logical operation. The key is scoped to the verified payer/network and bound to the validated request.

It does not replay the original paid response. A new authorization with a fresh nonce can charge again without a stable key. A retained conflict or ambiguous result must be resolved before considering another payment.
