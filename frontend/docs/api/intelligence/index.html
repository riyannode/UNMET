Demand Intelligence API

Filter funded demand and receive an inspectable comparison of matching opportunities.

LIMITED · X402 PAYMENT REQUIRED

Request

POST /v1/opportunities accepts an application/json object, up to 32 KiB, with the optional fields below. Unknown fields, arrays, null bodies, and invalid values are rejected before payment. {} uses defaults.

FieldDefaultAccepted value
minBounty"0"Non-negative decimal string with at most six fractional digits; current escrow in market-token units.
minSupporters1Integer from 0 to 4,294,967,295.
status"open"open, submitted, ready, rejected, expired, fulfilled, closed; case-insensitive. Supplied null is invalid.
sort"bounty"bounty, supporters, calls, deadline, score; case-sensitive.
limit10Integer from 1 to 50. No cursor or offset pagination.

This unsigned request receives a payment challenge, not paid results. Follow the x402 payment flow to authorize the returned terms.

Paid response

A successful response contains chainId, contract, blockNumber, generatedAt, analysis, and opportunities.

Top-level analysis contains poolSize, rankingScope, scoreVersion, marketToken, and tokenDecimals. Scope is matching_filters_before_limit; score version is escrow-percentiles-v1; decimals are 6.

Each opportunity retains the public demand fields and adds:

FieldMeaning
rankUnique 1-based rank by rounded score, then numeric demand ID descending. Response order is independently controlled by sort.
scoreBreakdownFunding, expectedCalls, and supporters each expose percentile/contribution. deadlineFreshness exposes factor/contribution.
economicSignalsescrowPerExpectedCall, timeRemainingSeconds, and review. Review is null unless the stored state is submitted.
reasoningDeterministic positive and cautions arrays. These are interpretations of indexed facts, not AI predictions.

Review signals contain approvalGap and rejectionHeadroom as six-decimal market-token strings, plus reviewTimeRemainingSeconds as a decimal integer string. timeRemainingSeconds is also a non-negative decimal integer string.

Ranking and units

The score combines current-escrow percentile (50%), expected-call percentile (25%), supporting-wallet percentile (15%), and remaining-deadline freshness (10%, capped at 30 days). A longer remaining deadline increases freshness; urgency does not increase it.

For a pool larger than one, a percentile is the number of strictly smaller peer values divided by pool size minus one. A singleton has percentile 1; equal values in a larger pool have percentile 0. Contributions are summed and rounded to six decimals.

Ranks and scores use the full matching pool before the limit. Changing filters can change ranks. Changing only sort or limit does not. Free scores use a different pool and may differ.

escrowPerExpectedCall is current atomic escrow divided by historical expected calls, rounded down and formatted with six decimals; null when calls are zero. It is not service price or guaranteed revenue. Zero remaining time or approval gap does not prove settlement.

Limitations

Payment buys analysis, not escrow funding or service execution. A paid result may have an empty opportunity list. Supporting wallets are not independent people; expected calls are not observed usage. Scores do not establish profit, quality, or fulfillment probability.

Full schemas are available in OpenAPI. Keep EVM integer strings as strings or exact integers, not floating-point numbers.
