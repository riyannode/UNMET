API overview

Read public demand facts for free. Use paid intelligence when you need a ranked comparison.

Access and discovery

Use the origin serving your UNMET API. The public-site origin is https://unmetxyz.my.id; a different instance may use another origin. These examples describe the interface and do not establish current endpoint availability.

Public reads require no account or API key. Paid intelligence uses x402 authorization. There is no OAuth login or UNMET client SDK requirement.

Machine clients should send Accept: application/json. OpenAPI is available at /openapi.json; compact guides are /api.md and /payment.md. The API catalog links the existing business endpoints.

Free demand API

GET /v1/demands returns up to 50 demands across all statuses, sorted by current escrow descending, then numeric demand ID descending. It has no query-filter or pagination contract. Query-string values do not filter the result.

Response fields

The envelope contains chainId, contract, blockNumber (decimal string), generatedAt (ISO timestamp), and demands. An empty list is valid.

Demand fieldsMeaning and units
demandId, capabilityDecimal-string ID and capability slug. IDs belong to the identified chain and contract.
creator, builderWallet addresses. Builder may be the zero address before a proposal.
currentEscrow, fundedBounty, reviewCommittedSix-decimal market-token strings. Current escrow is still held; reviewCommitted is a fixed review snapshot; fundedBounty uses the review snapshot when present, otherwise current escrow.
maxUnitPrice, expectedCalls, supportersSix-decimal price string, decimal-string expected calls, and integer supporting-wallet count. Calls/wallet totals are historical demand signals.
deadline, statusISO deadline, or null outside the supported date range; lifecycle/derived status.
approvalWeight, approvalRequired, rejectionWeight, rejectionThresholdAtomic integer strings, not decimal token amounts.
candidateRejected, scoreBoolean rejection indicator and legacy numeric demand score. No paid analysis fields are included.

Status and freshness

Stored states are OPEN, SUBMITTED, FULFILLED, CLOSED, and CANCELLED. Derived states include READY (quorum reached), REJECTED (quorum blocked), and EXPIRED. Check review conditions before acting.

Results are derived from an indexed block, not a live balance guarantee. Verify current onchain state for an escrow action. Responses use Cache-Control: no-store. Browser clients must use an origin allowed by the instance's CORS policy.

Service checks

GET /live checks process liveness, GET /health checks market dependencies, and GET /ready also checks payment readiness. None guarantees that a later payment will settle. See errors and recovery for failures.
