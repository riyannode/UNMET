API overview

Read public demand facts for free. Use paid intelligence when you need a ranked comparison.

Access and discovery

Use the origin serving your UNMET API. The public-site origin is https://unmetxyz.my.id; a different instance may use another origin. These examples describe the interface and do not establish current endpoint availability.

Public reads require no account or API key. Paid intelligence uses x402 authorization. There is no OAuth login or UNMET client SDK requirement.

Machine clients should send Accept: application/json. OpenAPI is available at /openapi.json; compact guides are /api.md and /payment.md. The API catalog links the existing business endpoints.

Free demand API

POST /v1/demands/prepare is free unsigned creation preparation. Send the configured chain/contract, canonical capability, v1 description and economic fields as documented in the API reference. It shares the frontend encoder, trims the description and returns only chainId, to, data and zero native value. It never signs, broadcasts, approves tokens or invokes payment.

Demand discovery includes raw onchain specification unchanged. The human frontend displays recognized v1 descriptions while retaining historical plain-text compatibility.

GET /v1/services and GET /v1/services/:id are free reads of fulfilled demand services. The snapshot hash identifies the indexed block, not the fulfillment block. See the API reference for response fields and errors.

GET /v1/demands returns up to 50 demands across all statuses, sorted by current escrow descending, then numeric demand ID descending. It has no query-filter or pagination contract. Query-string values do not filter the result.

Response fields

The envelope contains chainId, contract, escrowToken, blockNumber (decimal string), generatedAt (ISO timestamp), and demands. An empty list is valid.

Status and freshness

Stored states are OPEN, SUBMITTED, FULFILLED, CLOSED, and CANCELLED. Derived states include READY (quorum reached), REJECTED (quorum blocked), and EXPIRED. Check review conditions before acting.

Results are derived from an indexed block, not a live balance guarantee. Verify current onchain state for an escrow action. Responses use Cache-Control: no-store. Browser clients must use an origin allowed by the instance's CORS policy.

Builder validation

POST /v1/x402/validate runs in a separately configured validator. The base stack does not include it; an opt-in overlay provides validator, signer and observer with Caddy ingress. Strict JSON requests are limited to 32 KiB. The validator checks EOA or ERC-1271 builder authorization, inspects an unpaid challenge, then requests a signature from the signer. HTTP 200 PASS includes an attestation and signature; HTTP 400 FAIL and HTTP 503 UNAVAILABLE have no attestation. PASS does not prove paid execution or service quality. See proposal fields and flow.

Service discovery

Free services are identified by chain, contract and demand ID and retain fulfillment provenance. Builders publish signed metadata with PUT /v1/services/:chainId/:contract/:demandId/discovery; EOA or ERC-1271 authorization binds the canonical builder and service. Higher revisions replace, lower revisions conflict, and equal revisions are idempotent only for identical payloads.

List filters are capability (case-insensitive substring), network, asset, maxPrice and state. Network and lowercase asset match exactly; atomic uint256 maxPrice requires both network and asset. Payment filters must match the same current compatible offer, and filtering precedes the 50-result limit. Metadata state is missing, valid or invalid; cached observation state is pending, metadata_invalid, compatible, incompatible, unavailable or stale. An observation is not a guarantee of availability or paid execution. See the compact reference and OpenAPI.

Service checks

GET /live checks process liveness, GET /health checks market dependencies, and GET /ready checks payment and activity storage readiness before health. Readiness does not prove complete history or future settlement. See errors and recovery for failures.
